# goBaDig v1.4.0 — "NEW" / msx-tokenizer (build 0)

**Data**: 2026-11-21
**Bloco (`X`)**: `NEW`
**Feature (`Y`)**: `msx-tokenizer`
**Build (`Z`)**: `0`

## Resumo

Primeira conversão de BASIC de verdade: o tokenizer MSX Batoken
(ASCII numerado → binário `.bmx`) portado por completo para Go.

## O que tem nesta release

- Novo pacote `internal/platforms/msx`: tabela de ~150 tokens
  transcrita em ordem (ordem de varredura importa, como no original),
  codificação de inteiros em três faixas, números decimais (não
  binários — ver abaixo), `&H`/`&O`/`&B`, alvos de `THEN`/`GOTO`,
  comentários `REM`/`'`, `DATA`, `CALL`, strings, identificadores.
- **Corrige uma suposição errada do `OUTLINE.md`**: o parsing
  numérico não usa Microsoft Binary Format nem nenhum formato binário
  de float — é puramente decimal (um byte de expoente + dígitos
  decimais empacotados, já que cada dígito é um nibble hex válido).
- Os 13 vetores de ouro do Bloco 0 passam byte-exato; validado contra
  mais 10 casos comparando diretamente com o Python original.

## O que não mudou / ainda falta

- Nenhuma conversão Dignified→Classic de verdade ainda
  (`Description`/`Lexer`/`Parser` MSX) — esta release só tokeniza
  texto Classic ASCII já numerado, escrito à mão. Ligar isso ao motor
  Dignified do Bloco 1 é o próximo passo.
- Notação científica em literais numéricos, literais com mais de
  ~18-19 dígitos, e espaço embutido dentro de um número não são
  suportados ainda (nenhum é comportamento real do MSX nem está
  coberto pelos vetores de ouro — ver `OUTLINE.md`, Bloco 2).

## Pacote

`goBaDig-v1.4.0.zip`: executável Windows, `README.md`, `CHANGELOG.md`,
`LICENSE`, `docs/MANUAL.md`, `docs/RESOURCES.md`, `examples/`. O
binário não muda de comportamento nesta release — `internal/platforms/msx`
ainda não é usado por nenhum outro pacote.

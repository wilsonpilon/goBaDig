# goBaDig v1.41.0 — "NEW" / file-manager (build 0)

**Data**: 2026-11-26

**Feature (`Y`)**: `file-manager`
**Build (`Z`)**: `0`

## Resumo

**Gerenciador de arquivos de dois painéis na TUI** — pedido do
usuário: "já que não temos os gerenciadores de arquivo ainda, podemos
seguir por este caminho e assim chamar o compilador do gerenciador,
criar projetos, etc.". VSIX/Sublime (Bloco 8) ficam deliberadamente
pro final — o WibEdit já embutido cobre edição.

## O que mudou

Novo pacote `internal/filemanager`: componente de tela cheia estilo
Norton Commander, dois painéis (`tview.Table`, colunas nome/tamanho/
data), navegação local (`Tab` troca painel, `Enter`/`Backspace`
entra/sai de diretório). Novo menu **`Files > Open`** na TUI abre o
gerenciador.

Atalhos disponíveis (mostrados na própria barra de status):

- `F2` compila o arquivo selecionado (`dialect.CompileByExtension`).
- `F9` executa no emulador padrão da plataforma
  (`dialect.RunInEmulatorByExtension`).
- `F4` abre o arquivo selecionado no WibEdit já embutido (novo
  `editor.Editor.OpenFile`).
- `F5` copia (só arquivo nesta rodada) e `F6` move (arquivo ou
  diretório, via `os.Rename`) pro painel oposto, com confirmação.
- `F7` cria um diretório; `F8` apaga um arquivo ou diretório vazio,
  com confirmação.
- `Ctrl+N` cria um **projeto** (nome, pasta — criada se não existir
  —, dialeto, com a opção de já gerar um arquivo-fonte inicial
  vazio).
- `Ctrl+P` lista projetos salvos e pula o painel ativo pra pasta
  escolhida.

Novo `internal/config/projects.go`: tabela `projects` no mesmo
`*Store` SQLite de temas/opções (`CreateProject`/`ListProjects`).
Configurações por projeto e editar/apagar um projeto já salvo ficam
fora desta rodada.

Novo pacote `internal/chrome`: os ícones/sombra/moldura de janela de
`internal/tui/chrome.go` extraídos pra um pacote compartilhado,
exportado — `internal/filemanager` precisa do mesmo visual retro, e
não podia importar `internal/tui` sem criar um ciclo de importação
(`internal/tui` importa `internal/filemanager` pra embutir a página,
igual já faz com o editor).

## Decidido com o usuário

- TUI primeiro, GUI depois — mesma decisão já tomada pro editor.
- Montagem de `.DSK` num painel e operações local↔`.DSK` ficam pra
  depois.
- "Projeto" = nome + pasta + dialeto + registro SQLite pra acesso
  rápido; configurações por projeto ficam pra depois.

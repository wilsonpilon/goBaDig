# goBaDig v1.36.0 — "NEW" / zxspectrum-parser (build 0)

**Data**: 2026-11-26
**Bloco (`X`)**: `NEW`
**Feature (`Y`)**: `zxspectrum-parser`
**Build (`Z`)**: `0`

## Resumo

`Parser` ZX Spectrum (Bloco 4, Etapa 3 de 5) — fecha o motor de
conversão: **o primeiro arquivo `.dzs` real já compila de ponta a
ponta** (Lex→Parse→Generate), mesmo ponto que MSX e ZX81 chegaram
antes de ganhar seus próprios comandos `compile`/`execute`.

## O que tem nesta release

- `zxspectrum.Parser`/`zxspectrum.NewParser` (`core.Parser`):
  - `LET` implícito (depois de número de linha, `:` ou `THEN`).
  - `PRINT AT` via `[?](row,col)` — macro simples, sem default
    independente por coordenada (diferente do ZX81).
  - Atribuição composta (`+=`/`-=`/`*=`/`/=`/`^=`/`++`/`--`), com RHS
    completo embrulhado em parênteses.
  - `TRUE`/`FALSE`→`1`/`0`, normalização `GOTO`/`GOSUB`→`GO TO`/
    `GO SUB`, maiúscula incondicional de palavra reservada, limite
    de linha 9999.
  - Validação de identificador por categoria (sem alocador — nomes
    nativos de qualquer comprimento são válidos).
- 23 testes automatizados novos.

## Validação

- Extensiva, rodando o `badig.py` real (não só os testes
  automatizados): atribuição composta, `PRINT AT`, `GOTO`/`GOSUB`,
  maiúscula de palavra reservada, colisão com palavra reservada da
  ROM, e as 4 mensagens de erro de atribuição composta batem exato.
- `go build`/`go vet`/`gofmt`/`go test ./...` limpos no repositório
  inteiro.

## O que não mudou / ainda falta

- `REMX` continua fora de escopo (mesma decisão do ZX81).
- Nenhum comando `compile`/`execute` pro Spectrum ainda — próxima
  Etapa (4 de 5: validação de ponta a ponta contra programas reais;
  Etapa 5: `compile`/`execute` no CLI).
- Roteiro completo documentado em `OUTLINE.md`, Bloco 4.

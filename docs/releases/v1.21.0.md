## Resumo

Primeira etapa de um recurso maior, pedido pelo usuário: um painel
de configuração persistido em SQLite para todas as opções que o
`badig.py` original expõe por CLI/`.ini`/remtag (numeração de linha,
cabeçalho REM, TAB, espaçamento, relatórios, tokenizer, emulador —
uma por dialeto), editável na UI e via comandos `SET` no CLI. Esta
release entrega só a base: o catálogo de opções e o schema SQLite
que as armazena.

## O que tem nesta release

- Pacote novo `internal/options`: catálogo embutido com 40 opções em
  4 categorias — **Basic Dignified** (geral, 14 opções: numeração de
  linha, cabeçalho REM, TAB, espaçamento, relatórios), **MSX** (14:
  conversões de `PRINT`/`THEN`/`GOTO`, tokenizer, emulador openMSX),
  **ZX81** (4: tokenizer, emulador EightyOne) e **ZX Spectrum** (8:
  modelo de ROM, tokenizer de fita, emulador). Cada opção tem tipo
  (`bool`/`int`/`string`/`enum`), valor padrão e validação.
- `internal/config.Store` ganha `SetOption`/`GetOption`/
  `ListOptions`/`EnsureOptionDefaults`, numa tabela SQLite nova —
  mesmo padrão já usado pelo sistema de temas: valida antes de
  gravar, só semeia o valor padrão na primeira vez, nunca sobrescreve
  um valor que o usuário já mudou.
- 18 testes novos.

## O que não mudou / ainda falta

- Nenhum comando `SET` no CLI ainda (próxima etapa).
- Nenhum painel de configuração na TUI/GUI ainda (etapas seguintes).
- Nenhum valor configurado aqui é lido pelo pipeline de conversão
  real ainda — isso é consumo futuro, um passo separado.
- Só a camada global de configuração existe; a camada "projeto" e a
  resolução das 4 camadas (SQLite global < projeto < CLI < remtags no
  código) seguem adiadas, documentadas no `OUTLINE.md`.

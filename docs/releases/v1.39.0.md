# goBaDig v1.39.0 — "NEW" / emulator-backends (build 0)

**Bloco (`X`)**: `NEW`
**Feature (`Y`)**: `emulator-backends`
**Build (`Z`)**: `0`

## Resumo

**Seleção de emulador alternativo** — pedido do usuário depois de
perceber que MSX, ZX81 e ZX Spectrum agora têm mais de um emulador
instalado nesta máquina (ZEsarUX, fMSX, blueMSX+, além dos padrões
já existentes). Nova flag `--emulator <nome>` no CLI, `execute
<arquivo> [emulador]` no console.

## O que tem nesta release

- `internal/cli/dialect.go`: `emulatorBackends` (lista de nomes
  válidos por extensão, primeiro = padrão) + `resolveBackend`.
- **MSX**: `fmsx`/`bluemsx+` como alternativas ao `openmsx` (padrão).
- **ZX81**: `zesarux` como alternativa ao `eightyone` (padrão).
- **ZX Spectrum**: `zesarux` como alternativa ao `eightyone`
  (padrão) — bem mais simples de integrar: `--machine 48k --tape
  <arquivo>`, sem nenhum perfil INI.
- ZEsarUX deliberadamente fora do MSX (só emula MSX1 — openMSX/fMSX/
  blueMSX+ cobrem MSX2/MSX2+ também, decisão do usuário).

## Bug corrigido

`--emulator` ANTES de `--execute`/do nome do arquivo (exatamente a
forma documentada no `--help`) fazia o CLI confundir o nome do
emulador com o arquivo a executar, já que sempre tomava literalmente
o próximo token depois de `--execute`. Corrigido removendo a flag
`--emulator`+valor de `args` antes de qualquer outra detecção de
argumento posicional rodar.

## Validação

- Os 4 backends novos (fMSX, blueMSX+, ZEsarUX para ZX81 e Spectrum)
  confirmados abrindo de verdade nesta máquina, incluindo através da
  flag `--emulator` (ambas as ordens) e do comando `execute` do
  console.
- `go build`/`go vet`/`gofmt`/`go test ./...` limpos no repositório
  inteiro.

## O que não mudou / ainda falta

- Nenhum backend usa nenhum protocolo de controle remoto (como o
  ZRCP do ZEsarUX) ainda — é só abrir o emulador com o arquivo
  certo, mesmo nível dos emuladores padrão.
- TUI/GUI ainda não chamam nenhum comando `compile`/`execute`, em
  nenhuma plataforma.

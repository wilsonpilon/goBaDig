## Resumo

**Comando `compile`/`execute` pro ZX Spectrum** (Bloco 4, Etapa 5 de 5
— roteiro completo). Os comandos já existentes (MSX/ZX81) agora
também escolhem ZX Spectrum pela extensão do arquivo:
`goBaDig programa.dzs`/`goBaDig --execute programa.dzs` funcionam de
verdade. **Ciclo ZX Spectrum completo via CLI, igual MSX e ZX81.**

## O que tem nesta release

- `internal/cli/dialect.go`: `.dzs`→ZX Spectrum nos dois
  dispatchers (`compileByExtension`/`runInEmulatorByExtension`).
- `internal/platforms/zxspectrum/compile.go` (`CompileFile`,
  `DefaultCompileSettings`) e `run.go` (`RunInEmulator`).
- `RunInEmulator` precisa de um perfil INI do EightyOne — dois
  argumentos posicionais (`[ini, fita]`), diferente de MSX/ZX81 (um
  só). O perfil 48K vem embutido como string Go; uma cópia temporária
  é escrita a cada chamada, nunca edita o original.

## Decidido com o usuário

O `emulator_interface.py` original do Spectrum espera o EightyOne
fechar antes de retornar (`process.wait()`, falha se o emulador sair
com erro); MSX/ZX81 no Go não esperam. Escolhida a **consistência
entre as três plataformas no Go** (não esperar), não a fidelidade ao
Python nesse ponto específico.

## Validação

- Um processo `EightyOne.exe` real, lançado de verdade por
  `goBaDig --execute`, confirmado rodando nesta máquina.
- Testes automatizados novos (`compile_test.go`/`run_test.go` no
  pacote `zxspectrum`, mais os pares `.dzs` dos testes já existentes
  em `internal/cli`).
- `go build`/`go vet`/`gofmt`/`go test ./...` limpos no repositório
  inteiro.

## O que não mudou / ainda falta

- `REMX` e o modelo 128K na integração de emulador continuam fora de
  escopo (documentado no `OUTLINE.md`, Bloco 4).
- TUI/GUI ainda não chamam nenhum desses comandos, em nenhuma das
  três plataformas.
- DignifieR Spectrum (AZS→DZS), ZEsarUX/ZRCP, snapshots Z80/SNA —
  backlog de fases tardias, ver `OUTLINE.md`, Bloco 4.

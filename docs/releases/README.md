# docs/releases/

Um arquivo por versão publicada, nomeado `vX.Y.Z.md`, com o **mesmo
conteúdo** que vai na página de Releases do GitHub para aquela versão
(não um resumo à parte — é a fonte de verdade que se cola/publica lá).

Conteúdo esperado de cada `vX.Y.Z.md`:

- Nome da versão e, se houver, o nome do bloco grande (`X`) e o nome
  resumido da feature (`Y`) — ver esquema de versionamento no
  `CHANGELOG.md`.
- Data de lançamento.
- Resumo do que mudou nesta versão (features, correções, limitações
  conhecidas).
- Lista de assets do pacote (`goBaDig-vX.Y.Z.zip` e o que ele contém).
- Instruções mínimas de instalação/uso, se diferirem da versão anterior.
- Créditos/agradecimentos quando aplicável.

Nenhum release foi publicado ainda — esta pasta está vazia além deste
README. O primeiro arquivo real só deve ser criado junto com a primeira
tag/release de fato.

# goBaDig v1.31.0 — "NEW" / zx81-parser (build 0)

**Data**: 2026-11-24
**Bloco (`X`)**: `NEW`
**Feature (`Y`)**: `zx81-parser`
**Build (`Z`)**: `0`

## Resumo

Etapa 3 de 5 do módulo ZX81: o `Parser`. Com `Description`/`Lexer`
(v1.30.0) e o tokenizer (v1.29.0) já prontos, o **primeiro arquivo
`.dzx` real já compila de ponta a ponta** (Lex→Parse→Generate). Falta
só ligar os comandos `compile`/`execute` (o tokenizer já está pronto)
e validar no emulador.

## O que tem nesta release

- Alocação de variável de 1 letra (descendente, `z`,`y`,`x`...),
  reusando `core.NewDescendingAllocator()` sem nenhuma mudança.
- `LET` implícito: `a=1` vira `let a=1` automaticamente, já que o
  BASIC clássico do ZX81 não tem atribuição nua.
- `PRINT AT`: `[?](row,col) "texto"` → `print at row,col;"texto"`,
  com cada coordenada ausente defaultando pra `0` independentemente.
- `core.BuiltinDefine` ganha um campo novo, `Expand` — uma evolução
  pequena e precisa do contrato pra viabilizar o `PRINT AT`, sem
  precisar de uma reestruturação maior do `Parser`.
- 12 testes automatizados de ponta a ponta, todos confirmados contra
  o `badig.py` real antes de virar teste.

## Achados

- `~` (a marca Dignified "mantenha o nome longo") é sempre um erro
  fatal pro ZX81 — diferente do MSX, o BASIC clássico do ZX81 não
  tem como representar um nome de variável com mais de 1 caractere.

## O que não mudou / ainda falta

- `remx` (diretiva Dignified) e a renumeração de listagem numerada
  colada direto ficam de fora desta etapa — são hooks que envolvem o
  pipeline inteiro no Python original, não passes do `Parser`;
  exigiriam uma evolução de arquitetura maior. Documentado em
  `OUTLINE.md`, Bloco 3.
- Nenhum comando `compile`/`execute` pro ZX81 ainda (Etapa 5).
- EightyOne já está instalado nesta máquina, mas a validação real no
  emulador só acontece na Etapa 5.

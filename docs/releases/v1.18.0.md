# goBaDig v1.18.0 — "NEW" / remheader (build 0)

**Data**: 2026-11-23
**Bloco (`X`)**: `NEW`
**Feature (`Y`)**: `remheader`
**Build (`Z`)**: `0`

## Resumo

Cabeçalho REM automático de 2 linhas + expansão de TAB pra espaços —
os dois últimos gaps conhecidos contra a saída real do `badig.py`.
Com isso, o `CGK173.dmx` inteiro (891 linhas) agora bate **byte a
byte**, sem nenhuma diferença restante.

## O que tem nesta release

- Cabeçalho REM automático de 2 linhas (`"Converted with Basic
  Dignified"` / `"https://github.com/farique1/basic-dignified"`),
  inserido no início do arquivo principal quando
  `CompileSettings.RemHeader` é `true`.
- Expansão de TAB pra espaços durante o carregamento do arquivo
  (`core.LoadLines`), controlada por `CompileSettings.TabLength`.
- Correção de uma suposição documentada errada na release anterior
  (v1.17.0): o offset constante de +20 encontrado ali não era "o
  Python reserva 2 números de linha pro cabeçalho mesmo com `-rh`
  desligado" — era simplesmente que o arquivo de referência usado
  pra comparar tinha sido gerado COM o cabeçalho de verdade (sem
  passar `-rh`), e este port ainda não gerava essas 2 linhas.

## Validação

Com os dois gaps fechados, o `CGK173.dmx` inteiro produz saída
**idêntica, byte a byte** (diff vazio) à saída real do `badig.py`
rodando num Python de verdade nesta máquina — a primeira validação
de ponta a ponta 100% completa, sem nenhuma diferença conhecida
restante.

## O que não mudou / ainda falta

- Pass 1 do separador Dignified `_` fora do fim de linha (semântica
  ainda não entendida).
- Nenhum wiring de CLI real ainda expõe `-rh`/`-tl` (ou qualquer
  outra flag) pro usuário final — por isso `RemHeader`/`TabLength`
  usam zero-value `false`/`0` por padrão, invertido do default real
  do Python, até essa integração existir.
- Próximo passo: ligar tudo isso ao tokenizer MSX Batoken (já pronto
  desde a v1.4.0) pra fechar o caminho completo até o binário `.bmx`.

## Pacote

`goBaDig-v1.18.0.zip`: executável Windows, `README.md`,
`CHANGELOG.md`, `LICENSE`, `docs/MANUAL.md`, `docs/RESOURCES.md`,
`examples/`. O binário não muda de comportamento visível pro usuário
final nesta release (motor de conversão interno, ainda não exposto
por nenhuma interface).

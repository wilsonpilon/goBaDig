## Resumo

Primeira peça do módulo **ZX81** (Bloco 3): o tokenizer. Converte
texto Classic ASCII ZX81 já numerado numa imagem `.p` completa,
pronta pra carregar num emulador (EightyOne) — a mesma peça que, no
MSX, veio antes de qualquer Description/Lexer/Parser Dignified.

## O que tem nesta release

- `internal/platforms/zx81.Tokenize(lines []string) ([]byte, error)`:
  texto numerado → imagem `.p` completa (system vars + programa +
  display file + variáveis).
- Ponto flutuante oculto do ZX81 (bias de expoente 128, diferente do
  IEEE754 e do Microsoft Binary Format do MSX).
- Diretiva `remx <linha>,<count>[,<byte>]` (reserva de bytes crus
  dentro de uma linha REM, comum pra código de máquina embutido).
- Escapes hexadecimais `\{XX}` e aspas duplicadas `""` dentro de
  string.
- `docs/golden-vectors/zx81-tokenizer.md`, 27 testes automatizados.

## Validação

- Os 27 testes do `test_tokenizer_zx81.py` real (projeto Python
  original) continuam passando nesta máquina.
- Validação cruzada ad-hoc: a mesma entrada, tokenizada pelo Python
  real e pelo port Go, produz o mesmo buffer byte a byte.

## O que não mudou / ainda falta

- Nenhum Description/Lexer/Parser ZX81 ainda — nenhum arquivo `.dzx`
  Dignified compila de verdade. Esse tokenizer só processa texto
  Classic ASCII **já numerado** (o formato intermediário que viria do
  Lexer/Parser, ainda não implementados).
- Nenhum comando `compile`/`execute` pro ZX81 ainda.
- **EightyOne não está instalado nesta máquina** — a validação real
  de abrir um `.p` no emulador fica pra quando essa etapa chegar.
- Roteiro completo das próximas etapas documentado em
  `OUTLINE.md`, Bloco 3.

# goBaDig v1.30.0 — "NEW" / zx81-lexer (build 0)

**Data**: 2026-11-24
**Bloco (`X`)**: `NEW`
**Feature (`Y`)**: `zx81-lexer`
**Build (`Z`)**: `0`

## Resumo

Etapa 2 de 5 do módulo ZX81: `Description` e `Lexer`, o vocabulário
clássico do dialeto e o scanner que classifica texto ZX81 Dignified
real. Ainda sem `Parser` — nenhum arquivo `.dzx` compila de ponta a
ponta ainda (falta a Etapa 3).

## O que tem nesta release

- `internal/platforms/zx81/description.go`: vocabulário completo (31
  instruções, 3 funções `$`, 21 funções planas, 4 jump keywords, 3
  operadores, símbolos incluindo os 4 compostos
  `<>`/`>=`/`<=`/`**`), 1 letra de variável.
- `internal/platforms/zx81/lexer.go`: reconhece esse vocabulário de
  verdade, mais o escape hex `\{XX}` (token próprio) e string
  literal com `\"` e `""` coexistindo como escape de aspas.
- 11 testes automatizados, incluindo 9 casos documentando um
  comportamento peculiar de número com sinal, confirmado rodando o
  `badig.py` real (`-lex -prr`): um sinal só funde com o número
  seguinte quando imediatamente adjacente a um dígito puro — nunca
  atravessa um ponto decimal nem um expoente.

## Achados

- O ZX81 real **não tem** o atalho `''` de bloco de comentário
  clássico que o MSX tem — confirmado lendo o código-fonte das duas
  plataformas lado a lado. O mecanismo genérico já existente no
  `core` lida com isso automaticamente, sem nenhum código extra.
- `internal/core/allocator.go` já previa o esquema de variável de 1
  letra do ZX81 desde antes deste port começar.

## O que não mudou / ainda falta

- `Parser` ZX81 (alocação de variável, `PRINT AT`, `LET` implícito,
  `remx` como diretiva Dignified, renumeração de listagem numerada) —
  Etapa 3 do roteiro.
- Nenhum comando `compile`/`execute` pro ZX81 ainda.
- **EightyOne** já está instalado nesta máquina
  (`D:\zeddy\eightyone`), mas a validação real no emulador só
  acontece na Etapa 5.

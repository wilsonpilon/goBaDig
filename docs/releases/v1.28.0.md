## Resumo

Fecha o ciclo MSX completo pelo CLI: **editar → compilar → testar
num emulador real**, exatamente o fluxo descrito desde o início do
projeto (`edit programa.dmx`, `goBaDig programa.dmx`, `goBaDig
--execute programa.dmx`).

## O que tem nesta release

- `goBaDig --execute <arquivo.dmx>` (CLI) ou `execute <arquivo.dmx>`
  (console `--cli`): compila o programa, empacota o resultado num
  disco `.dsk` novo — o programa compilado como `AUTOEXEC.BAS`, pra
  rodar sozinho assim que o disco dá boot, sem precisar digitar nada
  — e abre o openMSX com esse disco montado.
- `msx.BuildTestDisk`/`msx.RunInEmulator`: as duas funções por trás
  disso, reutilizando a biblioteca `.DSK` (v1.26.0) e o comando
  `compilar` (v1.27.0) já existentes.
- Validado com um processo `openmsx.exe` real, lançado de verdade
  pelos dois pontos de entrada (CLI e console).
- 12 testes automatizados novos.

## O que não mudou / ainda falta

- Nenhum protocolo de monitoramento de erro em tempo real (mapear
  erro de execução pra linha Dignified de origem) — fica pra uma
  rodada futura, já adiada desde o início do projeto.
- Nenhuma opção de máquina/extensão/configuração do emulador
  configurável pela linha de comando ainda.
- Os arquivos reais de sistema MSX-DOS (`MSXDOS.SYS`/`COMMAND.COM`)
  não são embutidos no disco de propósito — são software de
  terceiros sob copyright. O disco gerado mostra um breve "Boot
  error" antes de cair pro `AUTOEXEC.BAS` sozinho; não é um bug.
- TUI e GUI ainda não chamam nenhum desses comandos.

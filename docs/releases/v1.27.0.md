## Resumo

A primeira conversão Dignified→binário disponível de verdade pro
usuário final — não só testada internamente, como em toda release
anterior do motor. Todas as peças que esse comando usa (`core.Run`,
o tokenizer MSX Batoken, `core.LoadLines`) já existiam e já tinham
sido validadas sozinhas; esta release é a orquestração que finalmente
liga tudo num comando real.

## O que tem nesta release

- `goBaDig <arquivo.dmx>` (CLI, sem nenhuma opção) converte um
  programa MSX Basic Dignified real, gerando `<arquivo>.amx`
  (listagem Classic numerada) e `<arquivo>.bmx` (binário tokenizado)
  no mesmo diretório do arquivo de entrada.
- O console interativo (`--cli`) ganha o comando irmão `compile
  <arquivo.dmx>`.
- Usa os mesmos defaults reais do `badig.py` original (numeração a
  partir de 10, passo 10, cabeçalho REM de 2 linhas, TAB expandido em
  4 colunas).
- Validado byte a byte, nos dois arquivos de saída, contra o
  `CGK173.dmx` inteiro (891 linhas) convertido pelo `badig.py` real
  nesta máquina.
- 9 testes automatizados novos.

## O que não mudou / ainda falta

- Nenhuma flag de linha de comando lê/aplica as opções persistidas
  pelos painéis de configuração (CLI/TUI/GUI) ainda — usa sempre os
  defaults.
- Nenhum caminho de saída customizável (sempre ao lado do arquivo de
  entrada, mesmo nome base); nenhuma seleção de dialeto por flag (só
  MSX tem motor de conversão).
- TUI e GUI ainda não chamam esse comando.
- A visão maior (copiar o resultado pra uma pasta, gerar um disco
  `.DSK` com ele dentro, testar num emulador de verdade) fica pra uma
  rodada futura — as duas peças que ela precisa (a biblioteca `.DSK`
  da v1.26.0, e este comando) já existem.

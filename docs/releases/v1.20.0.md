# goBaDig v1.20.0 — "NEW" / tokenizer-wiring (build 0)

## Resumo

Ligação do pipeline de conversão (`core.Run`) ao tokenizer MSX
Batoken (`internal/platforms/msx/tokenizer.go`, pronto desde a
v1.4.0) — a primeira conversão Dignified→binário `.bmx` de ponta a
ponta de verdade.

## O que tem nesta release

- `msx.CompileToBinary(ctx, platform) ([]byte, error)`: roda o
  pipeline textual inteiro (`Lex`/`Parse`/`Generate`, via
  `core.Run`) e tokeniza o resultado direto em memória, sem passar
  por disco — mesma ideia do fluxo original (que salva o texto
  Classic e depois tokeniza o arquivo salvo), só que os dois estágios
  já estavam no mesmo formato (`GenerateResult.Code []string`) e não
  precisaram de nenhum round-trip.
- 2 testes novos: a ligação em si (confirmada contra uma chamada
  equivalente feita na mão) e a propagação de um erro de Parse através
  dela.

## Validação

`CGK173.dmx` inteiro (891 linhas) compilado direto pra `.bmx` binário
bate **byte a byte** (18.815 bytes) contra o `.bmx` real gerado por
`python badig.py CGK173.dmx CGK173.amx --tk_tokenize` nesta máquina —
a primeira validação de ponta a ponta até o binário, não só até o
texto Classic.

## O que não mudou / ainda falta

Nenhum wiring de CLI real ainda expõe essa conversão pro usuário
final (nenhuma das três interfaces chama `CompileToBinary` hoje) —
isso é o próximo passo natural, junto com expor as flags/Settings do
MSX (`-cp`/`-tg`, item já adiado desde o Bloco 2) e portar os outros
dois dialetos (ZX81/ZX Spectrum), que ainda não têm nenhum
`Description`/`Lexer`/`Parser` próprio.

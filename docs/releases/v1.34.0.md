## Resumo

Primeira peça do módulo **ZX Spectrum** (Bloco 4): o tokenizer.
Converte texto Classic ASCII já numerado em bytes tokenizados — a
mesma peça que, no MSX e no ZX81, veio antes de qualquer
Description/Lexer/Parser Dignified.

## O que tem nesta release

- `internal/platforms/zxspectrum.Tokenize(source, model string)
  ([]byte, error)`: texto numerado → bytes tokenizados (`model` é
  `"48"` ou `"128"`).
- Ponto flutuante Sinclair exato via `math/big` (`Rat`/`Int`), não
  `float64` — o Spectrum real usa `decimal.Decimal`+
  `fractions.Fraction` (aritmética racional exata), diferente do ZX81
  (que usa `float64`/IEEE754 porque o Python original também usa
  `float64` ali). Bias de expoente `+129` (ZX81 usa `+128` — ROM
  diferente).
- `DEF FN` com os 6 bytes ocultos por parâmetro (marcador `0x0E`+5
  zeros) que a ROM usa pra cachear o valor avaliado em runtime.
- Escapes `\{XX}` (byte cru), `\XX` (gráfico, 37 códigos) e `%A`..`%U`
  (21 UDGs).
- `MakeTap`/`MakeTzx` (`tape.go`) — empacotamento de fita, 100%
  mecânico.
- 19 testes automatizados, portados dos vetores de ouro reais do
  `test_zxspectrum.py` do projeto Python original.

## Validação

- Os 19 testes Go passam, confirmados byte a byte contra os vetores
  reais do `test_zxspectrum.py` (`TokenizerTests`/`TapeTests`).
- `go build`/`go vet`/`gofmt`/`go test ./...` limpos no repositório
  inteiro.

## O que não mudou / ainda falta

- Nenhum Description/Lexer/Parser Spectrum ainda — nenhum arquivo
  `.dzs` Dignified compila de verdade. Esse tokenizer só processa
  texto Classic ASCII **já numerado** (o formato intermediário que
  viria do Lexer/Parser, ainda não implementados).
- `REMX` deliberadamente fora de escopo nesta Etapa (mesma decisão já
  tomada pro ZX81, Bloco 3) — no Spectrum ele vive só no nível do
  Parser Dignified, não há superfície de tokenizer pra portar.
- Nenhum comando `compile`/`execute` pro Spectrum ainda.
- Roteiro completo das próximas etapas documentado em `OUTLINE.md`,
  Bloco 4.

## Resumo

**Correção de bug real**, reportada pelo usuário com uma captura de
tela depois da v1.41.2: o nome de quase todo diretório no gerenciador
de arquivos aparecia em branco — só a data da linha ficava visível.
As duas correções anteriores (v1.41.1/v1.41.2) miraram num problema
de cor porque o primeiro relato ("preto com preto") parecia um
problema de contraste — mas o problema nunca foi cor nenhuma.

## O que mudou

**Causa raiz real**: o `tview` trata qualquer trecho `[...]` como uma
tentativa de tag de estilo `[cor]`/`["região"]` sempre que o
caractere logo depois do `[` é letra, dígito, `#`, `:` ou `-` — casado
e CONSUMIDO (zero caracteres visíveis), quer a "cor" dentro resolva
pra algo real ou não. O formato `"[" + nome + "]"` usado pelos
diretórios (estilo Norton Commander) colidia direto com isso:
`"[..]"` sobrevivia por acidente (o caractere depois do `[` é `.`,
inválido como início de tag), mas `"[cmd]"`, `"[docs]"`,
`"[internal]"` — qualquer diretório real começando com letra ou
dígito — desaparecia por completo.

Confirmado isolando uma cópia local do `rivo/tview` com
instrumentação (mesma técnica já usada uma vez neste projeto, pro bug
do `SetBackgroundColor` em `Grid`): `printWithStyle` realmente
retornava zero caracteres impressos para `"[aaa]"`, e todos os 4 para
`"[..]"`.

Corrigido com `tview.Escape` (a própria ferramenta documentada do
`tview` para esse caso exato) em:

- `internal/filemanager/panel.go`'s novo `entryLabel` (nome do
  arquivo/diretório) e o título do painel (caminho do diretório).
- A barra de status (mensagens de erro frequentemente citam o
  caminho que falhou).
- A lista de projetos salvos (nome/pasta do projeto, digitados pelo
  usuário).
